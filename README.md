# Общий чат

Первая рабочая версия веб-чата на Node.js и настоящем WebSocket. Проект развивается: сейчас все вошедшие участники общаются в одной комнате без сохранения истории на сервере.

## Возможности

- Вход по имени, сообщения кнопкой или Enter.
- Имя и время назначаются сервером; собственные сообщения приходят через общую рассылку.
- Уведомления о входе и выходе, счётчик участников, состояние соединения.
- Автоматическое восстановление соединения и входа, отключение и ручное повторное подключение.
- Сворачиваемый журнал последних 100 событий WebSocket.
- Светлый адаптивный интерфейс на русском без внешних ресурсов.

## Требования и запуск

Node.js 22 или новее и npm. Команды для PowerShell из каталога проекта:

```powershell
npm ci
npm start
```

Откройте http://127.0.0.1:3000 в двух вкладках или окнах и войдите под разными именами. Остановка: Ctrl+C.

Другой порт:

```powershell
$env:PORT = '3001'
npm start
# После остановки верните значение по умолчанию:
Remove-Item Env:PORT
```

Сервер слушает только `127.0.0.1`; другие устройства к нему не подключаются. HTTP и WebSocket используют один порт, путь WebSocket — `/ws`.

## Проверка

```powershell
npm test
```

Интеграционные тесты используют `node:test` и два настоящих клиента `ws`. Проверяют вход, счётчик, обмен в обе стороны, единственную собственную копию, серверные имя и время, выход, валидацию и работу после ошибок. Дополнительно проверяются HTTP-ресурсы и предел размера кадра. Тесты запускают сервер на свободном локальном порту и закрывают его после проверки.

Проверки клиентского кода выполняются с минимальной DOM-моделью: управляемое время проверяет задержки, обратный отсчёт, сброс задержки, отмену попыток и защиту от запоздавших событий. Отдельный тест останавливает и заново запускает настоящий сервер, проверяя автоматический вход двух клиентов и обмен после восстановления. Это не заменяет браузерную проверку разметки и взаимодействия.

Ручная проверка: откройте два окна, войдите, обменяйтесь сообщениями. Остановите сервер, проверьте блокировку отправки, сброс счётчика и обратный отсчёт. Запустите сервер и дождитесь входа без нажатия кнопок. Убедитесь, что старые сообщения остались, черновик не отправился, новые сообщения приходят по одному. Повторите обрыв и нажмите «Отключиться» во время ожидания: попытки должны прекратиться. После этого проверьте ручное подключение и журнал событий.

## Переподключение

После неожиданного события `close` клиент повторяет подключение через 1, 2, 4, 8, затем каждые 10 секунд. Статус показывает обратный отсчёт и номер попытки. Событие `error` только отображает и записывает ошибку; новый цикл начинается после `close`. Одновременно используется один WebSocket и один таймер ожидания, который также обновляет отсчёт.

Имя хранится в памяти вкладки. При открытии нового соединения клиент автоматически отправляет `join`, но разрешает отправку сообщений только после `welcome`. Подтверждённый вход сбрасывает задержку до 1 секунды. При отказе во входе попытки прекращаются: причина показана над сообщениями, имя можно исправить и подключиться вручную.

Кнопка «Отключиться» закрывает текущее соединение, отменяет таймер и выключает повторы. Она доступна и во время ожидания, и во время подключения. Повторное ручное подключение снова включает восстановление. События предыдущих соединений игнорируются.

Уже показанные сообщения и черновик остаются в текущей вкладке. Очереди отправки и автоматической повторной отправки нет. После потери связи появляется одно локальное системное уведомление, после успешного повторного входа — «Соединение восстановлено. Сообщения за время отсутствия не восстановлены». Счётчик при отсутствии связи показывает «—», затем обновляется событием `presence` от сервера. Локальные уведомления не отправляются другим участникам.

## Протокол

Каждое событие — отдельное текстовое JSON-сообщение с полем `type`. Сначала клиент отправляет `join`, дожидается `welcome` и только затем отправляет `chat`.

Клиент → сервер:

```json
{"type":"join","name":"Анна"}
{"type":"chat","text":"Привет!"}
```

Сервер → клиент (значения идентификатора и времени приведены как примеры):

```json
{"type":"welcome","id":"connection-uuid","name":"Анна"}
{"type":"chat","id":"connection-uuid","name":"Анна","text":"Привет!","time":"2026-11-12T12:00:00.000Z"}
{"type":"system","text":"Анна входит в чат","time":"2026-11-12T12:00:00.000Z"}
{"type":"presence","count":1}
{"type":"error","message":"Некорректный JSON."}
```

`welcome` и `error` адресованы одному соединению. `chat`, `system` и `presence` рассылаются только вошедшим участникам, включая отправителя. После `welcome` приходят уведомление о входе и актуальный `presence`; при выходе — уведомление и новый счётчик. Порядок участников с одинаковыми именами различается по `id`; повторный вход по одному соединению запрещён.

Имя сохраняется в состоянии соединения. Переданные клиентом имя и время в `chat` игнорируются. `time` — серверное время ISO 8601 в UTC, интерфейс отображает его в местном времени браузера. Имя и текст обрезаются по краям; длины — 1–30 и 1–1000 единиц UTF-16 (как `String.length` и HTML `maxlength`). Пустые значения, неверные типы, неизвестные события, массивы, бинарные сообщения и некорректный JSON вызывают `error`. Дополнительные поля игнорируются. `maxPayload` — 16 КиБ; превышение закрывает соединение с кодом 1009. Обычная ошибка валидации не закрывает соединение.

## Отладка

Раскройте «События WebSocket»: журнал показывает местное время, `→` для отправки, `←` для получения и `•` для событий соединения. Для разрыва указаны код и причина, для повторов — задержка, номер попытки и результат входа. В нём остаются последние 100 записей, в том числе после переподключения.

В DevTools браузера откройте Network → WS, выберите `/ws` и вкладку Messages (название зависит от браузера). Сравните кадры с журналом интерфейса. Console показывает ошибки JavaScript. Введённый текст выводится через `textContent`.

## Ограничения и развитие

Это первая рабочая версия, не продукт для промышленной эксплуатации. Нет учётных записей, уникальности имён, комнат, сохранения истории, heartbeat и ограничения частоты сообщений. Имя — представление участника, а не подтверждённая личность. При перезагрузке вкладки история исчезает; при переподключении в той же вкладке остаётся только уже показанная история. Пропущенные сообщения не восстанавливаются. История интерфейса пока не ограничена по количеству сообщений. Восстановление начинается только после события `close` от браузера: обнаружение «зависшего» соединения без этого события пока не реализовано.

Ближайшие улучшения: heartbeat, ограничение частоты и объёма рассылки, предел истории интерфейса, браузерные тесты. Для публичного развёртывания отдельно потребуются HTTPS/WSS, проверка Origin, управление доступом и защита от перегрузки.

Исходники можно хранить на GitHub, но публикация репозитория сама по себе не запускает сервер. GitHub Pages обслуживает статические файлы и не запускает эту серверную часть Node.js.
